Perfis Operacionais:
Estrutura e Aplicação

Este bloco define os perfis operacionais da No Fire e traduz a estrutura técnica de controle de acessos em funções reais dentro do sistema, estabelecendo padrões claros para concessão, restrição e governança de acesso por perfil.

1. Objetivo do Bloco 08

Este bloco tem como objetivo traduzir toda a estrutura técnica de controle de acesso em perfis operacionais reais utilizados na No Fire.

Até este ponto do manual foram apresentados:

  • estrutura de acesso (PBCA079, PBCA079A, PBCA035, PBCA035C);
  • regras de vinculação de programas;
  • regras de restrição por usuário;
  • permissões internas por checkbox.

A partir deste bloco, essas definições passam a ser aplicadas em perfis reais.

Perfil não é conceito técnico. Perfil é função operacional aplicada ao sistema.

2. O que é um perfil operacional

Um perfil operacional representa um conjunto de acessos que refletem a função real de um usuário dentro da empresa.

O perfil não representa:

  • uma pessoa específica;
  • um usuário isolado;
  • uma exceção;
  • uma necessidade temporária;
  • um improviso.

O perfil representa:

  • uma função;
  • um conjunto de responsabilidades;
  • um padrão de acesso replicável;
  • uma base para controle e auditoria.

Perfil deve ser replicável. Se só serve para uma pessoa, provavelmente está errado.

3. Princípio da padronização

A No Fire deve trabalhar com um número reduzido de perfis bem definidos.

Quanto mais perfis forem criados:

  • maior a dificuldade de controle;
  • maior a chance de erro;
  • maior a dificuldade de auditoria;
  • maior a inconsistência operacional.

Poucos perfis bem definidos são mais seguros do que muitos perfis mal definidos.

4. Perfis base definidos para a No Fire

A estrutura inicial de perfis deve considerar as áreas operacionais da empresa.

Perfis base sugeridos:

  • VENDEDOR
  • ADMINISTRATIVO
  • FINANCEIRO
  • RH
  • ENGENHARIA
  • GESTOR
  • ADMINISTRADOR

Esses perfis podem ser ajustados conforme validação da operação, mas devem ser mantidos como base.

Perfis devem nascer da estrutura da empresa, não da tela do sistema.

5. Perfil VENDEDOR

O perfil VENDEDOR representa usuários que atuam diretamente na operação comercial, com foco em orçamento, pedido e relacionamento com cliente.

Objetivo do perfil

  • realizar orçamentos;
  • gerar pedidos;
  • consultar preços;
  • acompanhar vendas.

Programas esperados

  • PBCA032 — Orçamento de Venda;
  • PBCA015 — Pedido de Venda;
  • PBCA069 — Consulta de Preços;
  • PBCA097 — Consulta de Preços;

Restrições obrigatórias

  • não acessar cadastro de produtos;
  • não acessar tabelas de preço;
  • não acessar financeiro;
  • não acessar tributação;
  • não acessar utilitários;

Checkboxes críticos bloqueados

  • alterar valor do produto;
  • alterar desconto;
  • excluir pedido;
  • cancelar pedido;
  • aprovar orçamento;

Vendedor opera venda. Não altera estrutura, não define preço, não controla sistema.

6. Perfil ADMINISTRATIVO

O perfil administrativo representa usuários que atuam no suporte à operação, incluindo atividades financeiras, cadastro e controle interno.

Objetivo do perfil

  • executar rotinas administrativas;
  • operar financeiro conforme função;
  • manter cadastros autorizados;

Programas esperados

  • PBCA027 — Títulos;
  • PBCA074 — Conta Corrente;
  • PBCA031 — Boletos;
  • PBCA030 — Movimentações;

Restrições obrigatórias

  • não acessar perfil e vinculação;
  • não acessar exportação;
  • não acessar funções fiscais críticas sem validação;

Administrativo executa operação. Não define acesso nem estrutura.

7. Perfil FINANCEIRO

O perfil financeiro possui acesso a rotinas críticas relacionadas a valores, pagamentos, recebimentos e conciliações.

Objetivo do perfil

  • gerenciar contas a pagar e receber;
  • realizar baixas;
  • executar conciliação;
  • controlar fluxo financeiro;

Programas esperados

  • PBCA027 — Títulos;
  • PBCA074 — Conta Corrente;
  • PBCA139 — Caixa;
  • PBCA152 — Conciliação;

Ponto crítico

Este perfil deve ser extremamente controlado.

Acesso financeiro exige controle. Não existe “financeiro básico”.

8. Perfil RH

O perfil RH possui atuação restrita ao cadastro e manutenção de usuários e funcionários, conforme definido no treinamento específico.

Objetivo do perfil

  • cadastrar funcionários;
  • cadastrar usuários;
  • atualizar dados cadastrais;

Programas esperados

  • PBCA056 — Funcionários;
  • PBCA035C — Cadastro de Usuários (limitado);

Restrições obrigatórias

  • não acessar perfil;
  • não acessar vinculação;
  • não acessar restrição de usuário;
  • não acessar financeiro;

RH cadastra. RH não define acesso.

9. Perfil ENGENHARIA

O perfil ENGENHARIA representa usuários que atuam em rotinas técnicas, operacionais e estruturais, principalmente relacionadas a equipamentos, serviços e execução técnica.

Objetivo do perfil

  • operar rotinas técnicas;
  • consultar dados de equipamentos;
  • interagir com CADEX;
  • acompanhar execução operacional;

Programas esperados

  • PBCA101, PBCA102, PBCA103 — Processos;
  • PBCX001, PBCX003 — CADEX;
  • PBCA082 — Obras (quando aplicável);

Restrições obrigatórias

  • não acessar financeiro;
  • não acessar cadastro de preços;
  • não acessar perfil e permissões;
  • não acessar tributação;

Engenharia executa operação técnica. Não define regras comerciais ou financeiras.

10. Perfil GESTOR

O perfil GESTOR representa usuários que possuem visão gerencial da operação, com acesso a relatórios, acompanhamento e análise de dados.

Objetivo do perfil

  • acompanhar resultados;
  • analisar desempenho;
  • visualizar relatórios;
  • tomar decisões;

Programas esperados

  • GESTOR01 a GESTOR06;
  • Relatórios BI;
  • PBRE (relatórios operacionais);

Ponto de atenção

Este perfil pode ter acesso a dados sensíveis, incluindo:

  • faturamento;
  • margem;
  • comissões;
  • dados financeiros;

Gestor precisa ver tudo. Mas não precisa alterar tudo.

11. Perfil ADMINISTRADOR

O perfil ADMINISTRADOR é o perfil mais sensível do sistema.

Ele pode ter acesso a:

  • cadastro de usuários;
  • perfil e vinculação;
  • restrições;
  • financeiro;
  • tributação;
  • parâmetros;
  • exportação de dados;

Esse perfil não deve ser utilizado como solução para evitar configuração.

ADMINISTRADOR não é perfil padrão. É perfil de risco controlado.

Regras obrigatórias

  • uso restrito a pessoas autorizadas;
  • uso apenas quando necessário;
  • responsabilidade total sobre ações executadas;
  • não utilizar para operação comum;

12. Regra de exceção

Nem todas as necessidades serão atendidas diretamente pelos perfis padrão.

Quando houver exceção:

  1. não criar novo perfil automaticamente;
  2. avaliar se pode ser tratado na PBCA035;
  3. avaliar se pode ser tratado por checkbox;
  4. validar com responsável;
  5. documentar a exceção;

Exceção deve ser controlada. Não virar regra.

13. Quando criar um novo perfil

Um novo perfil só deve ser criado quando:

  • existe função recorrente;
  • existe grupo de usuários com comportamento comum;
  • perfil atual não atende;
  • a diferença não pode ser tratada por restrição;

Não criar perfil quando:

  • é um único usuário;
  • é situação temporária;
  • é exceção pontual;

Novo perfil sem critério = perda de controle.

14. Checklist de validação de perfil

Antes de considerar um perfil pronto:

  1. perfil representa função real?
  2. programas vinculados estão corretos?
  3. programas críticos foram avaliados?
  4. restrições na PBCA035 foram aplicadas?
  5. checkboxes foram revisados?
  6. existe acesso indireto possível?
  7. existe risco financeiro?
  8. existe risco estrutural?
  9. perfil é replicável?

Perfil só está pronto quando passa pelo checklist completo.

15. Erros que devem ser evitados

  • criar perfil por usuário;
  • duplicar perfil sem revisar;
  • liberar acesso por pressa;
  • usar ADMINISTRADOR como solução fácil;
  • não revisar PBCA035;
  • não revisar checkboxes;
  • não validar com operação;

Perfil errado não dá erro imediato. Ele cria problema silencioso.

16. Conclusão do Bloco 08

O controle de acesso do CAD ERP depende diretamente da qualidade dos perfis definidos.

Perfis mal estruturados geram:

  • acesso indevido;
  • erro operacional;
  • risco financeiro;
  • perda de controle;

Perfis bem definidos permitem:

  • controle;
  • padronização;
  • auditoria;
  • segurança operacional;

O sistema não controla acesso. O perfil bem definido controla.
