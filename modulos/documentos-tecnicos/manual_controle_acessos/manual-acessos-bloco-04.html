Cadastro de Perfil de Usuários
PBCA079

Este bloco explica a função real da tela Cadastro de Perfil de Usuários no CAD ERP, esclarecendo que o perfil serve como agrupador organizacional e não como controle completo de permissões.

1. Objetivo do Bloco 04

O objetivo deste bloco é explicar, de forma objetiva e operacional, como funciona a tela Cadastro de Perfil de Usuários — PBCA079.

Essa tela é simples, mas precisa ser compreendida corretamente. Ela não define permissões, não libera programas e não restringe ações. Sua função é cadastrar o nome de um perfil, que depois poderá ser utilizado em outras etapas de configuração de acesso.

PBCA079 cria o nome do perfil. A liberação real de programas e permissões acontece em outras telas.

2. Caminho da tela

Para acessar a tela Cadastro de Perfil de Usuários, utilizar o seguinte caminho:

Menu Utilitários > Perfil de Usuários > (Tela) Cadastro de Perfil de Usuários - PBCA079

Esse caminho deve ser utilizado sempre que houver necessidade de cadastrar um novo nome de perfil no sistema.

3. Função real da PBCA079

A PBCA079 serve para cadastrar descrições de perfis de usuários. Na prática, ela funciona como uma pequena tabela de nomes de perfis.

Exemplos de perfis cadastrados ou possíveis:

  • VENDEDOR;
  • ADMINISTRADOR;
  • ENGENHARIA;
  • ADMINISTRATIVO;
  • USUARIO_VENDAS;
  • SEM_PERFIL.

Tela Cadastro de Perfil de Usuários - PBCA079.

A tela apresenta uma grade simples. Ao clicar em Adicionar, o sistema cria uma nova linha, permitindo informar a descrição do perfil.

Esta tela cadastra apenas o nome do perfil. Ela não configura o que o perfil pode acessar.

4. Como cadastrar um novo perfil

Para cadastrar um novo perfil na PBCA079:

  1. Acessar o menu Utilitários;
  2. Acessar a opção Perfil de Usuários;
  3. Aguardar a abertura da tela Cadastro de Perfil de Usuários - PBCA079;
  4. Clicar em Adicionar;
  5. Informar o nome do perfil na nova linha criada;
  6. Clicar em Salvar.

Após salvar, o perfil passa a existir como opção no sistema. Porém, nesse momento ele ainda não possui, necessariamente, programas vinculados ou restrições configuradas.

Perfil criado não significa perfil pronto para uso. Após criar o nome, ainda é necessário definir programas e revisar acessos.

5. Quando criar um novo perfil

A criação de novos perfis deve ser tratada com critério. Não é necessário criar um perfil novo para cada usuário, nem para cada pequena variação operacional.

Um novo perfil só deve ser criado quando houver uma diferença real e recorrente de função ou necessidade de acesso.

Exemplos de situações que podem justificar um novo perfil:

  • criação de uma nova área operacional;
  • grupo de usuários com acesso padrão diferente dos perfis existentes;
  • necessidade de separar funções com risco diferente;
  • definição formal de uma nova função pela gestão;
  • reorganização operacional validada pela No Fire.

Perfil deve representar função operacional. Não deve ser criado por improviso.

6. Quando não criar novo perfil

Nem toda necessidade de ajuste exige criação de perfil. Muitas diferenças devem ser tratadas em telas posteriores, principalmente na restrição direta por usuário.

Não criar novo perfil apenas porque:

  • um usuário precisa de uma exceção pontual;
  • um usuário temporariamente precisa acessar algo a mais;
  • existe pequena diferença entre dois usuários da mesma área;
  • alguém pediu acesso por conveniência;
  • não se sabe ainda qual será a matriz definitiva;
  • o perfil existente ainda não foi corretamente revisado.

Nesses casos, o correto é avaliar a necessidade, revisar a matriz e, se aplicável, tratar a diferença diretamente por usuário na etapa adequada.

Perfil demais também vira descontrole. Criar perfil sem necessidade aumenta confusão e dificulta auditoria.

7. Papel da PBCA079 dentro do fluxo completo

A PBCA079 é apenas uma etapa inicial dentro do fluxo de controle de acessos. Ela deve ser entendida dentro da seguinte sequência:

  1. PBCA035C — Cadastro de Usuário;
  2. PBCA079 — Cadastro do nome do perfil;
  3. PBCA079A — Vinculação do perfil aos programas;
  4. PBCA035 — Restrição de usuário por programa;
  5. PBCA035C — Revisão de checkboxes internos, quando aplicável.

Portanto, a PBCA079 não deve ser analisada isoladamente. Ela é apenas o cadastro do agrupador que será usado depois.

PBCA079 organiza. PBCA079A vincula. PBCA035 restringe. PBCA035C refina.

8. Perfis previstos para a implantação

Durante os próximos passos da implantação, os perfis necessários serão criados e ajustados conforme a estrutura operacional definida para a No Fire.

Como a tendência é que os perfis principais sejam cadastrados previamente durante a implantação, a PBCA079 provavelmente será pouco utilizada na rotina comum após essa configuração inicial.

A criação ou alteração de perfis após a implantação deve ocorrer somente mediante necessidade real e validação da gestão.

A PBCA079 será mais usada na implantação do que na operação diária. Depois de criada a estrutura, o uso deve ser excepcional.

9. Padrão recomendado de nomenclatura

Os nomes dos perfis devem ser claros, objetivos e fáceis de compreender. O nome do perfil deve indicar a função ou área representada.

Recomenda-se evitar nomes genéricos, ambíguos ou pessoais.

9.1 Bons exemplos

  • VENDEDOR;
  • ADMINISTRATIVO;
  • ENGENHARIA;
  • RH;
  • FINANCEIRO;
  • GESTOR_COMERCIAL;
  • ADMINISTRADOR.

9.2 Exemplos que devem ser evitados

  • PERFIL_1;
  • TESTE;
  • NOVO;
  • USUARIO_DO_CARLOS;
  • FULANO;
  • ACESSO_ESPECIAL;
  • TEMPORARIO sem prazo definido.

Nome de perfil deve representar função, não pessoa, improviso ou exceção.

10. Perfil SEM_PERFIL

A existência de um perfil como SEM_PERFIL deve ser tratada com cuidado. Esse tipo de descrição pode ser útil para identificar usuários ainda não enquadrados em um perfil definitivo, mas não deve ser interpretado como garantia de bloqueio.

As auditorias realizadas demonstraram que um usuário sem perfil ou sem vínculo efetivo pode ainda assim acessar determinadas telas ou rotinas em alguns cenários.

Portanto, um usuário classificado como sem perfil deve ser tratado como pendente de validação e não como usuário automaticamente seguro.

SEM_PERFIL não significa sem risco. Usuário sem perfil também precisa de revisão.

11. Perfil ADMINISTRADOR

O perfil ADMINISTRADOR deve ser tratado como perfil de alto impacto. Ele não deve ser utilizado como solução simples para evitar configuração detalhada.

Usuários administradores podem ter acesso abrangente a funções críticas do sistema. Por isso, a atribuição desse perfil deve ser uma decisão consciente da gestão.

Quando houver usuário administrador, a regra operacional deve ser ainda mais rigorosa:

  • usar o acesso apenas dentro da função exercida;
  • não alterar estruturas sem necessidade;
  • não executar rotinas críticas por conveniência;
  • não usar acesso total como justificativa para ignorar o processo;
  • manter responsabilidade individual sobre as ações realizadas.

Administrador não é acesso livre. Administrador é responsabilidade ampliada.

12. Risco de perfis mal definidos

Um perfil mal definido pode gerar problemas operacionais mesmo que o cadastro tenha sido feito corretamente.

Riscos comuns:

  • usuários com acesso maior que o necessário;
  • usuários sem acesso a rotinas essenciais;
  • excesso de perfis parecidos;
  • dificuldade para auditar permissões;
  • uso de perfil genérico para funções diferentes;
  • confusão entre área, função e exceção individual.

Por isso, o cadastro de perfil deve ser simples, mas não deve ser feito de forma descuidada.

A tela é simples. O impacto da organização dos perfis não é.

13. Checklist antes de criar um perfil

Antes de criar um novo perfil na PBCA079, o responsável deve verificar:

  1. Esse perfil realmente representa uma função operacional?
  2. Já existe perfil equivalente?
  3. A necessidade é permanente ou apenas uma exceção?
  4. O nome do perfil é claro?
  5. A gestão validou a criação?
  6. Será possível definir programas para esse perfil na PBCA079A?
  7. Será possível auditar esse perfil depois?

Se a necessidade for apenas uma exceção individual, o caminho correto provavelmente não será criar um novo perfil, mas tratar a situação por regra operacional, restrição por usuário ou validação específica.

Novo perfil só deve existir quando houver motivo operacional claro.

14. O que fazer após criar o perfil

Após cadastrar o nome do perfil na PBCA079, o próximo passo é vincular os programas correspondentes ao perfil na tela PBCA079A.

Enquanto isso não for feito, o perfil existe apenas como descrição. Ele ainda não representa uma matriz de acesso operacionalmente válida.

O fluxo correto após a criação é:

  1. confirmar que o nome do perfil foi salvo corretamente;
  2. acessar a PBCA079A;
  3. vincular os programas adequados ao perfil;
  4. validar a coerência da vinculação;
  5. aplicar ou revisar restrições por usuário quando necessário;
  6. revisar checkboxes internos quando aplicável.

Criar o perfil é apenas o primeiro passo. O perfil só ganha utilidade quando programas são vinculados a ele.

15. Erros que devem ser evitados

  • achar que criar perfil libera acesso automaticamente;
  • criar perfil novo sem verificar se já existe equivalente;
  • usar nome de pessoa como nome de perfil;
  • criar perfil para exceção temporária;
  • usar perfil genérico para funções diferentes;
  • criar perfil e não vincular programas depois;
  • acreditar que SEM_PERFIL bloqueia tudo;
  • usar ADMINISTRADOR para evitar análise de permissões.

A PBCA079 é simples, mas o mau uso dela cria confusão em toda a governança de acessos.

16. Conclusão do Bloco 04

A tela Cadastro de Perfil de Usuários — PBCA079 tem uma função limitada e específica: cadastrar o nome dos perfis que serão utilizados na organização do acesso ao CAD ERP.

Ela não define permissões, não vincula programas e não substitui a revisão individual de acesso. Sua importância está em criar uma estrutura lógica inicial para que as demais etapas sejam organizadas.

O responsável pela configuração deve compreender que a PBCA079 é apenas o cadastro do agrupador. A construção efetiva do acesso acontece nas etapas seguintes, principalmente na PBCA079A, na PBCA035 e na revisão dos checkboxes da PBCA035C.

PBCA079 não concede poder. Ela apenas dá nome ao grupo que será configurado depois.
