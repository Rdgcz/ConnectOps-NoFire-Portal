Matriz Base de Permissões por PBCA

Este bloco organiza a matriz base de permissões por programa, relacionando os principais PBCAs aos perfis operacionais da No Fire e estabelecendo uma referência prática para liberação, restrição e revisão de acessos.

1. Objetivo do Bloco 09

O objetivo deste bloco é consolidar a matriz base de permissões por programa, utilizando os códigos PBCA como referência operacional para concessão e restrição de acesso no CAD ERP.

Até este ponto, o manual explicou a função de cada camada de controle: perfil, vinculação de programas, restrição por usuário e checkboxes internos. Agora, essas camadas são aplicadas em uma matriz prática.

A matriz de permissões é a referência operacional para decidir quem pode acessar o quê.

2. Como interpretar esta matriz

A matriz deve ser lida considerando três perguntas:

  1. Qual é o programa?
  2. Qual é o impacto desse programa?
  3. Qual perfil realmente precisa acessá-lo?

A liberação de acesso não deve ser feita apenas pelo nome da tela. O correto é analisar o impacto da rotina que o programa permite executar.

O nome da tela ajuda. O risco real está na ação que ela permite.

3. Legenda da matriz

Símbolo Significado Interpretação operacional
✔ Liberado O perfil pode acessar, desde que respeite a função e os checkboxes aplicáveis.
❌ Bloqueado O perfil não deve acessar como regra operacional.
⚠️ Controlado Exige validação, restrição por usuário ou revisão adicional.
ADM Administrativo / financeiro autorizado Uso limitado a usuários administrativos ou financeiros com função definida.
MST Administrador / master Acesso amplo, tratado como risco assumido e responsabilidade ampliada.

A matriz não substitui a revisão por usuário. Ela orienta a configuração inicial.

11. Tratamento de exceções

Quando um usuário precisar de acesso fora do padrão do perfil, a situação deve ser tratada como exceção.

A exceção deve responder:

  1. Quem precisa do acesso?
  2. Qual programa será liberado?
  3. Por que o perfil padrão não atende?
  4. O acesso será temporário ou permanente?
  5. Existe risco financeiro, fiscal, estrutural ou de exportação?
  6. A gestão validou?
  7. A exceção foi registrada?

Exceção sem registro vira novo padrão informal. E padrão informal destrói governança.

12. Checklist da matriz antes de liberar usuário

Antes de considerar um usuário pronto para operar, conferir:

  1. O usuário está vinculado a uma função real?
  2. O perfil aplicado corresponde à função?
  3. Os PBCAs críticos estão bloqueados quando não aplicáveis?
  4. Os PBCAs financeiros estão bloqueados para não financeiros?
  5. Os PBCAs fiscais estão bloqueados para não fiscais?
  6. Os utilitários estão bloqueados para usuários operacionais?
  7. Os relatórios BI foram avaliados?
  8. O acesso a exportação foi bloqueado?
  9. As restrições na PBCA035 foram revisadas?
  10. Os checkboxes da PBCA035C foram revisados?
  11. Existe alguma exceção registrada?

Usuário sem revisão da matriz é usuário pendente.

13. Conclusão do Bloco 09

A matriz base de permissões por PBCA é a principal referência operacional para controlar acessos no CAD ERP.

Ela transforma a discussão abstrata sobre perfis em uma decisão objetiva: qual programa cada perfil deve ou não deve acessar.

Porém, a matriz não resolve tudo sozinha. Ela deve ser combinada com:

  • vinculação correta na PBCA079A;
  • restrição individual na PBCA035;
  • revisão de checkboxes na PBCA035C;
  • governança sobre exceções;
  • auditoria periódica.

A matriz é o mapa. A configuração é a execução. A auditoria é a confirmação.
