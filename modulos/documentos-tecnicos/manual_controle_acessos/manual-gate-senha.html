1. O que é o gate de senha

O gate de senha é uma página intermediária (manual-acesso-gate.html) posicionada entre o portal e o conteúdo do manual de controle de acessos. Quando o usuário clica no card do manual na seção de RH, é levado para essa página, onde precisa digitar a senha correta antes de visualizar o conteúdo.

O fluxo completo é:

  • Usuário clica em "Manual de Controle de Acessos" na seção de RH do portal.
  • O navegador abre manual-acesso-gate.html.
  • O usuário digita a senha e clica em Acessar.
  • Se a senha estiver correta, é redirecionado automaticamente para o primeiro bloco do manual.
  • A sessão fica ativa pelo tempo configurado — sem precisar digitar a senha novamente nesse período.
✅ Esta proteção é adequada para conteúdo interno não crítico em portais estáticos. O objetivo é evitar acesso casual, não substituir autenticação de sistema.

2. Como funciona tecnicamente

2.1 O que é um hash SHA-256

A senha nunca é armazenada como texto no arquivo. O que fica gravado é o hash SHA-256 — uma sequência de 64 caracteres gerada matematicamente a partir da senha. Esse processo é de mão única: não é possível descobrir a senha original a partir do hash.

Exemplo: a senha nofire2026 produz este hash:

abc86b0b774061986ccf59ba08a41e5fb34c5ac4f4c5047ec08adcb2e3807d34

Quando o usuário digita a senha no campo, o navegador calcula o hash do que foi digitado e compara com o hash gravado no arquivo. Se coincidirem, o acesso é liberado. A senha em si nunca trafega nem é armazenada em nenhum lugar.

⚠️ Quem inspecionar o código-fonte do arquivo verá o hash — mas não consegue reverter o hash para descobrir a senha. Isso é seguro para o nível de proteção que o gate oferece.

2.2 Controle de sessão

Após autenticar com sucesso, o gate salva uma marca na sessionStorage do navegador. Enquanto essa marca estiver válida (dentro do tempo configurado), o usuário não precisa digitar a senha novamente — ao acessar o gate, é redirecionado direto para o manual.

A sessionStorage é apagada automaticamente quando a aba ou janela é fechada. Acessar o portal em outra aba ou navegador exige nova autenticação.

🔒 Fechar a aba apaga a sessão. Novo acesso exige a senha novamente.
⚠️ Manter a aba aberta preserva a sessão até o tempo configurado expirar.

3. Como trocar a senha

Trocar a senha envolve dois passos: gerar o novo hash e substituir o hash antigo no arquivo.

3.1 Via terminal — recomendado

Funciona no Terminal do Mac, Linux ou no Git Bash / WSL no Windows.

  • Abra o terminal.
  • Digite o comando abaixo, substituindo NOVA_SENHA pela senha desejada. Não adicione espaços antes ou depois das aspas.
    terminalecho -n "NOVA_SENHA" | sha256sum

    Exemplo: echo -n "nofire2026" | sha256sum
    Saída: abc86b0b774061986ccf59ba08a41e5fb34c5ac4f4c5047ec08adcb2e3807d34 -

  • Copie os 64 caracteres antes do espaço e do traço ( -) no final. Esse é o hash.
  • Siga para o passo 3.3.
🚫 No Mac, use sempre echo -n (com o -n). Sem ele, o echo adiciona uma quebra de linha invisível e o hash gerado fica errado — a senha nunca vai coincidir.

3.2 Via console do navegador

Alternativa caso não tenha acesso a um terminal. Funciona em qualquer navegador moderno.

  • Abra qualquer página do portal no navegador.
  • Pressione F12 para abrir as ferramentas do desenvolvedor.
  • Clique na aba Console.
  • Cole o código abaixo, substituindo NOVA_SENHA, e pressione Enter:
    console do navegador(async () => { const buf = await crypto.subtle.digest( "SHA-256", new TextEncoder().encode("NOVA_SENHA") ); const hash = [...new Uint8Array(buf)] .map(b => b.toString(16).padStart(2, "0")) .join(""); console.log("%c" + hash, "color:#7ee787;font-size:14px;"); })();
  • O hash aparece em verde no console. Copie-o e siga para o passo 3.3.

3.3 Substituir o hash no arquivo

  • Abra o arquivo modulos/rh/manual-acesso-gate.html no editor (VS Code, Notepad++, etc.).
  • Use Ctrl+F para localizar:
    gate.htmlconst HASH_CORRETO =
  • Substitua apenas os 64 caracteres entre aspas pelo novo hash. Mantenha as aspas e o ponto-e-vírgula.
    resultado esperadoconst HASH_CORRETO = "SEU_NOVO_HASH_COM_64_CARACTERES";
  • Salve o arquivo e faça o deploy/push para o servidor normalmente.
  • Teste abrindo o gate no navegador e digitando a nova senha.
✅ O hash tem sempre exatamente 64 caracteres hexadecimais (0–9 e a–f). Se o seu tiver mais ou menos, algo deu errado na geração — refaça o processo.

4. Configurar o tempo de sessão

Define por quantos minutos o usuário permanece autenticado sem precisar digitar a senha novamente. Localize no arquivo:

gate.htmlconst SESSION_MINUTES = 120;

Exemplos de configuração:

sem expiração por tempoconst SESSION_MINUTES = 0;

A sessão dura até fechar a aba. Sem limite de tempo.

30 minutosconst SESSION_MINUTES = 30;

Após 30 min, o gate pede a senha novamente.

⚠️ Fechar a aba sempre encerra a sessão, independentemente do tempo configurado. A sessionStorage não persiste entre abas ou sessões do navegador.

5. Alterar o destino após login

Após autenticação correta, o gate redireciona para a página definida na variável DESTINO. Por padrão:

gate.htmlconst DESTINO = "./manual_controle_acessos/manual-acessos-bloco-01.html";

Para apontar para outro arquivo, substitua pelo caminho relativo correto a partir da localização do gate.

✅ O caminho é sempre relativo ao arquivo gate, não à raiz do projeto. Use ./ para a mesma pasta e ../ para subir um nível.

6. Limites desta proteção

O que o gate protege

  • ✅ Acesso casual: quem chega pelo portal e não sabe a URL direta precisará digitar a senha.
  • ✅ A senha nunca fica exposta em texto puro no código — apenas o hash.
  • ✅ A sessão expira ao fechar a aba, sem rastro de autenticação persistido.

O que o gate não protege

  • 🚫 Acesso direto pela URL dos arquivos do manual — quem souber o endereço exato acessa sem senha.
  • 🚫 Usuários que inspecionam o código-fonte conseguem ver o hash e o caminho de destino.
  • 🚫 Conteúdo crítico ou confidencial — para isso é necessária autenticação server-side.
⚠️ Esta solução é adequada para o nível descrito: conteúdo interno não crítico em portal estático. Para dados sensíveis, o correto é migrar para uma solução com backend e autenticação real.
