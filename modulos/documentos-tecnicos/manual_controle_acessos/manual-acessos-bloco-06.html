Manual Operacional · Controle de Acessos · Bloco 06/10

Restrição de Usuários x Programas
PBCA035

Este bloco explica como utilizar a tela Restrição de Usuários x Programas no CAD ERP, considerada a principal camada de revisão individual de acesso por usuário.

1. Objetivo do Bloco 06

O objetivo deste bloco é orientar o responsável pela governança de acessos sobre a tela Restrição de Usuários x Programas — PBCA035.

Esta tela deve ser tratada como uma das camadas mais importantes do controle de acesso do CAD ERP, porque atua diretamente sobre o usuário. Enquanto a PBCA079A monta uma base de programas por perfil, a PBCA035 permite revisar o acesso individual.

Isso é essencial porque usuários com o mesmo perfil podem ter responsabilidades diferentes, exceções diferentes ou níveis diferentes de risco.

Perfil organiza. PBCA035 revisa usuário por usuário. Sem revisão individual, o controle fica incompleto.

2. Caminho da tela

Para acessar a tela de restrição de usuários por programa, utilizar o caminho abaixo:

Menu Utilitários > Restrição de Usuários X Programas > (Tela) Restrição de Usuários X Programas - PBCA035

Tela Restrição de Usuários x Programas - PBCA035.

3. Função real da PBCA035

A PBCA035 deve ser utilizada para revisar, liberar ou restringir o acesso de um usuário específico a programas específicos do CAD ERP.

Ela não deve ser confundida com a PBCA079A. A PBCA079A trabalha com o perfil. A PBCA035 trabalha com o usuário.

Tela Base de controle Função Leitura operacional
PBCA079A Perfil Vincula programas ao perfil Define a base geral de acesso daquele grupo.
PBCA035 Usuário Restringe ou ajusta programas por usuário Valida se aquele usuário específico deve acessar aquele programa.

PBCA079A responde: “o perfil pode?”. PBCA035 responde: “este usuário específico pode?”.

4. Por que a PBCA035 é crítica

A PBCA035 é crítica porque corrige uma limitação importante da configuração por perfil: nem todo usuário de um mesmo grupo deve, necessariamente, ter exatamente o mesmo nível de acesso.

Além disso, o ambiente auditado demonstrou comportamento permissivo em alguns pontos do sistema. Por isso, a No Fire não deve depender apenas da configuração teórica do perfil.

A PBCA035 deve ser usada para:

  • validar acessos individualmente;
  • bloquear programas críticos para usuários que não devem acessá-los;
  • restringir rotinas sensíveis mesmo quando o perfil possui alguma liberação base;
  • tratar exceções de forma controlada;
  • reforçar a matriz de permissões;
  • reduzir o risco de acesso indevido por herança de perfil;
  • documentar a intenção de controle por usuário.

A PBCA035 deve funcionar como o “filtro individual” após a montagem da base do perfil.

5. O que deve ser analisado na PBCA035

Na PBCA035, o responsável deve analisar o acesso do usuário programa por programa. A leitura deve considerar tanto o código quanto o nome do programa.

A avaliação deve responder:

  1. Este programa faz parte da função do usuário?
  2. Este programa é operacional, sensível ou crítico?
  3. O usuário precisa apenas consultar ou também alterar?
  4. O programa permite inclusão, exclusão, impressão ou exportação?
  5. Existe risco financeiro, fiscal, comercial ou estrutural?
  6. Existe checkbox complementar na PBCA035C?
  7. Existe risco de acesso indireto mesmo com restrição?
  8. Esta liberação está coerente com a matriz de permissões?

A revisão na PBCA035 não é uma etapa mecânica. É uma análise de risco por usuário.

6. Campos e opções de controle

A tela PBCA035 apresenta o usuário selecionado e os programas relacionados ao controle de acesso. Conforme a estrutura visual da tela, podem existir colunas de ação como:

  • Consulta;
  • Alteração;
  • Inclusão;
  • Exclusão;
  • Impressão;
  • Exportação;
  • ou outras opções equivalentes de permissão operacional.

A lógica é simples: não basta saber se o usuário acessa a tela. É necessário saber o que ele poderá fazer dentro daquela rotina, quando a tela permitir esse nível de controle.

Acesso à tela e poder de ação dentro da tela são coisas diferentes.

7. Regra de ouro da PBCA035

A regra de ouro para esta tela é:

Liberar somente o necessário para a função do usuário e bloquear todo poder que não tenha justificativa operacional.

Em caso de dúvida, a postura correta não é liberar “para não atrapalhar”. A postura correta é validar com a gestão ou com o responsável pelo processo.

O excesso de acesso pode não gerar problema imediato, mas cria risco acumulado:

  • usuário mexendo em tela fora da função;
  • alteração estrutural indevida;
  • exclusão ou cancelamento não autorizado;
  • exposição de dados sensíveis;
  • uso indevido de exportações;
  • dificuldade de auditoria posterior.

Acesso concedido sem necessidade vira risco silencioso.

8. Estratégia recomendada de configuração

A estratégia recomendada para a No Fire é:

1. Partir do perfil

Usar a PBCA079A para montar a base de programas do perfil.

2. Revisar o usuário

Usar a PBCA035 para verificar se aquele usuário deve manter todos os acessos da base.

3. Remover excessos

Bloquear ou restringir programas que não façam sentido para aquele usuário específico.

4. Refinar permissões

Depois revisar checkboxes internos na PBCA035C, quando aplicável.

O fluxo correto é: base por perfil, revisão por usuário, refinamento por checkbox.

9. Programas que devem ser bloqueados para usuários operacionais comuns

Alguns programas devem ser tratados como bloqueio padrão para usuários operacionais comuns, salvo autorização formal e necessidade comprovada.

PBCA079 Cadastro de Perfil Criação ou alteração de agrupadores de acesso. Bloquear para quem não administra perfis.
PBCA079A Vinculação Perfil x Programas Altera base de acesso de perfis. Bloquear para perfis não responsáveis pela governança.
PBCA041 Exportação de Dados Extração de informações da base. Bloqueio padrão.
PBCA052 Liberação de Usuários Risco de liberação indevida. Bloqueio padrão.
PBCA013 Tributação Impacto fiscal. Bloquear salvo responsável fiscal/autorizado.
PBCA027 Títulos Impacto financeiro. Bloquear para usuários sem função financeira.
PBCA074 Movimentação Conta Corrente Impacto financeiro e bancário. Bloquear para usuários sem responsabilidade financeira autorizada.
PBCA139 Movimentação Caixa Diário Impacto financeiro direto. Bloquear para usuários sem responsabilidade financeira autorizada.
PBCA152 Conciliação Bancária Impacto financeiro crítico. Bloquear para usuários sem função financeira validada.

PBCA052 Liberação de Usuários Risco de alteração indevida de liberações. Bloquear para usuários comuns. Restrito à governança de acesso.

PBCA032 Orçamento de Venda Rotina comercial operacional. Permitir para vendedores quando fizer parte da função, com atenção aos acessos indiretos.
PBCA015 Pedido de Venda Rotina comercial operacional. Permitir conforme função comercial e fluxo definido.

A PBCA035 deve ser usada para bloquear o que não pertence à função do usuário, mesmo que o perfil tenha uma base ampla.

11. Revisão de permissões por ação

A PBCA035 deve ser analisada não apenas pelo nome do programa, mas também pelas ações disponíveis para aquele programa. A tela pode apresentar permissões como consultar, incluir, alterar, excluir, imprimir e exportar.

O responsável pela revisão deve avaliar se o usuário precisa realmente de cada tipo de ação.

Ação Leitura operacional Diretriz
Consultar Permite visualizar informações. Pode ser permitido com menor risco, mas ainda exige atenção em dados sensíveis.
Incluir Permite criar novos registros. Permitir somente quando a função exigir criação de registros.
Alterar Permite modificar registros existentes. Tratar como sensível. Alteração indevida pode comprometer a base.
Excluir Permite remover registros. Bloquear por padrão, salvo necessidade formal e controlada.
Imprimir Permite gerar documentos ou relatórios impressos/PDF. Permitir conforme função, observando exposição de dados.
Exportar Permite retirar dados para arquivo externo. Bloquear por padrão em dados sensíveis, financeiros, comerciais e estratégicos.

Acesso à tela não significa autorização para alterar, excluir ou exportar. A ação deve ser analisada separadamente.

12. Estratégia recomendada para revisão na PBCA035

A revisão por usuário deve seguir uma lógica conservadora:

  1. Selecionar o usuário correto.
  2. Identificar a função operacional do usuário.
  3. Comparar a função com o perfil atribuído.
  4. Listar os programas realmente necessários para a função.
  5. Bloquear programas críticos que não fazem parte da função.
  6. Reduzir ações sensíveis quando possível.
  7. Evitar exclusão e exportação como padrão.
  8. Registrar ou comunicar exceções relevantes.
  9. Revisar checkboxes na PBCA035C após a revisão de programas.

Essa abordagem evita que o usuário mantenha acessos herdados, indevidos ou incompatíveis com sua função.

Primeiro confirme a função. Depois valide programas. Só então ajuste permissões internas e exceções.

13. Exemplo prático: vendedor

Um usuário vendedor precisa executar rotinas comerciais, mas não deve administrar estrutura do sistema.

Para um vendedor, a PBCA035 deve ser usada para garantir que o acesso fique limitado à função comercial.

Programas que podem fazer sentido para vendedor

  • PBCA032 — Orçamento de Venda;
  • PBCA032-ITE — Itens do Orçamento;
  • PBCA015 — Pedido de Venda;
  • PBCA015-ITE — Itens do Pedido;
  • PBCA069 — Consulta de Preços;
  • PBCA097 — Consulta de Preços;
  • relatórios comerciais autorizados.

Programas que não devem fazer parte da rotina do vendedor

  • PBCA005 — Produtos de Compra, Venda e Serviço;
  • PBCA006 — Tabelas de Preços;
  • PBCA013 — Tributação;
  • PBCA027 — Títulos;
  • PBCA041 — Exportação de Dados;
  • PBCA079 — Cadastro de Perfil;
  • PBCA079A — Vinculação Perfil x Programas;
  • PBCA035 — Restrição de Usuários x Programas.

Vendedor vende. Vendedor não mantém estrutura, não altera tributação, não administra perfil e não controla acesso.

14. Exemplo prático: RH

O RH possui papel cadastral, mas não deve definir poder de acesso.

A PBCA035 deve confirmar que o RH possui acesso às rotinas necessárias para sua função, sem abrir telas de governança de permissão.

Programas relacionados ao RH

  • PBCA056 — Funcionários;
  • PBCA035C — Cadastro de Usuários, conforme limite operacional definido.

Programas que devem permanecer bloqueados ao RH como regra

  • PBCA079 — Cadastro de Perfil;
  • PBCA079A — Vinculação Perfil x Programas;
  • PBCA035 — Restrição de Usuários x Programas;
  • PBCA041 — Exportação de Dados;
  • rotinas financeiras, fiscais ou comerciais sem relação direta com a função.

RH cadastra e informa. RH não concede poder de acesso.

15. Exemplo prático: administrativo / financeiro

Usuários administrativos ou financeiros podem precisar de programas sensíveis. Por isso, a revisão na PBCA035 deve ser mais cuidadosa, não mais permissiva.

Programas financeiros devem ser liberados apenas quando houver função clara, responsável definido e coerência com a rotina exercida.

Programas que podem fazer parte da função administrativa/financeira

  • PBCA027 — Títulos;
  • PBCA074 — Movimentação Conta Corrente;
  • PBCA031 — Emissão de Boletos;
  • PBCA073 — Conta Corrente;
  • PBCA139 — Movimentação Caixa Diário;
  • PBCA152 — Conciliação Bancária.

Mesmo nesses casos, é necessário revisar ações internas, como baixa, aprovação, reabertura, alteração de dados chave e visualização de totais. Parte dessas permissões poderá depender também dos checkboxes da PBCA035C.

Função financeira exige acesso sensível. Acesso sensível exige revisão detalhada.

16. Acesso indireto: por que a PBCA035 não resolve tudo

A PBCA035 é a principal camada de controle técnico disponível, mas ela não elimina todos os riscos. A auditoria mostrou que podem existir acessos indiretos ou comportamentos fora da lógica esperada.

Um exemplo importante já identificado envolve o orçamento de venda.

  • Tela de origem: Orçamento de Venda - PBCA032I;
  • Ação: botão com três pontos <...>;
  • Tela aberta: Cadastro de Item/Produto - PBCA005C;
  • Risco: alteração de informações estruturais do produto/item.

Exemplo de acesso indireto a partir da tela Orçamento de Venda - PBCA032I.

Exemplo de tela aberta por acesso indireto: Cadastro de Item/Produto - PBCA005C.

Isso significa que, mesmo com restrições aplicadas, a No Fire deve manter regra operacional clara: se uma tela abrir por caminho indireto, o usuário só poderá utilizá-la se a ação fizer parte da sua função.

A PBCA035 reduz risco, mas não substitui governança. Acesso indireto continua sendo risco operacional.

17. Relação entre PBCA035 e PBCA035C

A PBCA035 controla programas. A PBCA035C pode conter permissões internas por checkbox.

Por isso, uma revisão completa de acesso não termina na PBCA035. Após revisar programas e ações, o responsável deve voltar à PBCA035C para revisar os checkboxes internos.

Exemplos de permissões internas que exigem revisão:

  • alterar valor do produto;
  • alterar desconto;
  • cancelar pedido;
  • excluir pedido;
  • aprovar orçamento;
  • aprovar títulos;
  • baixar títulos;
  • reabrir títulos;
  • alterar dados chave financeiros;
  • cancelar nota fiscal.

PBCA035 responde “qual programa?”. PBCA035C responde “qual poder interno?”.

18. Checklist de revisão na PBCA035

Antes de considerar um usuário revisado, o responsável deve conferir:

  1. O usuário selecionado está correto?
  2. A função do usuário foi confirmada?
  3. O perfil associado faz sentido?
  4. Os programas liberados pertencem à função?
  5. Programas críticos estão bloqueados?
  6. Programas financeiros foram revisados?
  7. Programas fiscais foram revisados?
  8. Programas de utilitários foram revisados?
  9. Exportações estão bloqueadas quando não necessárias?
  10. Exclusões estão bloqueadas quando não necessárias?
  11. Alterações estruturais estão bloqueadas para usuários operacionais?
  12. A revisão de checkboxes da PBCA035C foi feita?
  13. Alguma exceção precisa ser comunicada ou validada?

Usuário não revisado individualmente não deve ser considerado pronto para operação.

19. Erros que devem ser evitados

  • acreditar que o perfil já resolveu o acesso;
  • não revisar usuário por usuário;
  • permitir exclusão sem necessidade real;
  • permitir exportação por padrão;
  • deixar programas críticos liberados para usuários operacionais;
  • não bloquear financeiro para quem não é financeiro;
  • não bloquear fiscal para quem não é responsável fiscal;
  • ignorar acessos indiretos;
  • não revisar checkboxes após revisar programas;
  • considerar usuário pronto apenas porque consegue acessar o sistema.

O maior erro é tratar PBCA035 como formalidade. Ela é a principal barreira disponível.

20. Conclusão do Bloco 06

A tela Restrição de Usuários x Programas — PBCA035 é uma das ferramentas mais importantes para controle efetivo de acesso no CAD ERP.

Enquanto a PBCA079 cria o nome do perfil e a PBCA079A vincula programas ao perfil, a PBCA035 permite revisar o acesso diretamente por usuário. Essa revisão é essencial porque o perfil, isoladamente, não garante controle suficiente.

A PBCA035 deve ser usada para bloquear programas incompatíveis com a função, reduzir poderes indevidos e revisar ações sensíveis como alteração, exclusão, impressão e exportação.

Mesmo assim, a PBCA035 não elimina todos os riscos. Acessos indiretos e checkboxes internos da PBCA035C exigem revisão complementar e governança operacional.

PBCA035 é o controle individual. Sem revisão por usuário, a matriz de acesso fica incompleta.
