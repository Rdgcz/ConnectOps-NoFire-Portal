Manual Operacional · Controle de Acessos · Bloco 07/10

Permissões internas (checkboxes)
PBCA035C

Este bloco trata das permissões internas do usuário, definidas diretamente na tela de cadastro, e que podem liberar ações críticas independentemente do perfil ou dos programas vinculados.

1. Objetivo do Bloco 07

Este bloco tem como objetivo explicar como funcionam os checkboxes de permissões internas na tela de cadastro de usuários.

Essas permissões são extremamente sensíveis porque:

  • não dependem diretamente do perfil;
  • não dependem diretamente da vinculação de programas;
  • podem liberar ações críticas dentro de telas já acessíveis;
  • podem estar marcadas sem validação.

Os checkboxes da PBCA035C podem conceder poder real ao usuário, mesmo quando o restante da configuração está correta.

2. Caminho da tela

Menu Utilitários > Cadastro de Usuários > (Tela) Cadastro de Usuários - PBCA035C

Tela Cadastro de Usuários - PBCA035C.

3. O problema real dos checkboxes

Diferente das outras telas:

  • PBCA079 → apenas nome do perfil
  • PBCA079A → define programas
  • PBCA035 → restringe programas

A PBCA035C contém permissões que:

  • alteram comportamento dentro das telas;
  • permitem ações críticas;
  • não são visíveis diretamente na navegação;
  • podem ser esquecidas na revisão.

Checkbox errado = usuário com poder invisível.

4. Erro comum (grave)

Durante o cadastro do usuário:

  • checkbox já vem marcado;
  • ninguém revisa;
  • usuário entra no sistema com poder indevido.

Checkbox marcado por padrão deve ser tratado como NÃO VALIDADO.

5. Regra operacional obrigatória

A No Fire deve adotar a seguinte regra:

  • nenhum checkbox é confiável por padrão;
  • todo checkbox deve ser revisado;
  • permissões devem ser justificadas;
  • o que não for entendido não deve ser liberado.

Se não sabe o que o checkbox faz, NÃO libera.

6. Momento correto para configurar checkboxes

A ordem correta é:

  1. criar usuário
  2. definir perfil
  3. vincular programas
  4. restringir na PBCA035
  5. apenas depois ajustar checkboxes

Checkbox é ajuste fino. Nunca é ponto de partida.

7. Tipos de permissões internas

Os checkboxes estão organizados em grupos:

  • Financeiro
  • Compras
  • Gestão de Vendas
  • Cliente
  • CRM
  • CADEX
  • Nota Fiscal
  • WhatsApp / Integrações

Cada grupo pode conter permissões que:

  • alteram valor
  • aprovam operação
  • cancelam registros
  • liberam exceções

8. Exemplo de risco (crítico)

Mesmo com restrições corretas:

  • usuário acessa PBCA032I (orçamento)
  • clica em <...>
  • abre PBCA005C

Perfil correto + programa correto + checkbox correto + acesso por rotina indireta = acesso indevido.
Nestes casos, o controle de acessos deve ser regido por governança e gestão.

9. Regra de interpretação

Para cada checkbox, o responsável deve perguntar:

  • isso altera dados?
  • isso aprova algo?
  • isso ignora regra?
  • isso impacta financeiro?
  • isso impacta cliente?

Se a resposta for sim para qualquer um, o checkbox é sensível.

10. Matriz prática de checkboxes — visão geral

A matriz abaixo organiza os principais grupos de permissões internas identificados na PBCA035C. Ela deve ser usada como referência de análise antes de marcar ou manter qualquer checkbox ativo.

Grupo Tipo de permissão Risco Regra operacional
Financeiro Aprovar, baixar, reabrir ou alterar títulos Crítico Restrito a usuários financeiros autorizados.
Compras Comprar, aprovar cotação ou visualizar notas Alto Restrito a usuários com função de compras.
Gestão de Vendas Alterar valor, desconto, aprovar, cancelar ou excluir pedido Crítico Bloquear por padrão para vendedores. Liberar apenas exceções validadas.
Cliente Desbloquear cliente Alto Restrito à gestão ou responsável autorizado.
CRM Usuário CRM / visualização de preço Médio Liberar conforme função.
CADEX Usuário / desativar equipamento Alto Restrito a usuários técnicos autorizados.
WhatsApp Usar envio ou sessão WhatsApp Médio Liberar apenas para usuários que atendem clientes.
Nota Fiscal Cancelar NF Crítico Restrito. Não liberar para usuários comerciais comuns.

A regra padrão é: checkbox crítico nasce bloqueado. Só é liberado com motivo claro.

11. Checkboxes financeiros

As permissões financeiras devem ser tratadas como críticas. Elas podem permitir ações que impactam cobrança, pagamento, baixa, reabertura, dados financeiros e visualização de totais.

Permissão Impacto Diretriz
Aprova Títulos Autoriza movimentação ou validação financeira. Restrito.
Baixa Títulos Permite dar baixa financeira. Controlado.
Reabrir Títulos Permite desfazer baixa ou reabrir obrigação. Restrito.
Busca todos os títulos na tela Amplia visualização de dados financeiros. Controlado.
Alterar dados chave do título Permite alterar valor, vencimento ou dados sensíveis. Restrito.
Utilizar todos os portadores Permite operar com diferentes bancos/portadores. Restrito.
Visualiza totais financeiro Permite visualizar consolidações financeiras. Controlado.
Usa contas a receber Permite atuação em contas a receber. Controlado por função.
Usa contas a pagar Permite atuação em contas a pagar. Controlado por função.
Visualiza títulos funcionário Exposição interna. Restrito.
Visualiza títulos vendedor Exposição comercial/comissão. Restrito.

Usuário sem função financeira não deve ter checkbox financeiro marcado.

12. Checkboxes de compras

As permissões de compras devem ser liberadas apenas para usuários que participam diretamente do fluxo de compra, cotação, aprovação ou conferência fiscal relacionada.

Permissão Impacto Diretriz
É comprador Identifica usuário como operador de compras. Controlado.
Aprova cotação / ordem de compra Permite avanço ou aprovação no fluxo de compras. Restrito.
Visualiza NF funcionário Exposição de informações internas. Restrito.
Visualiza NF vendedor Exposição de informações comerciais/fiscais. Restrito.

Compra não é consulta genérica. Quem aprova compra assume impacto operacional e financeiro.

13. Checkboxes de gestão de vendas

Este é um dos grupos mais críticos para a operação comercial. Algumas permissões podem afetar preço, desconto, aprovação, cancelamento, exclusão, vendedor responsável e comportamento do pedido.

Permissão Impacto Diretriz
Antecipar pedido Altera fluxo comercial ou operacional. Controlado.
Reserva pedido Impacta disponibilidade/fluxo de atendimento. Controlado.
Copiar pedido Facilita rotina operacional. Baixo risco, mas revisar conforme perfil.
Retornar pedido para orçamento Reverte etapa do fluxo comercial. Restrito.
Permitir alterar valor do produto Impacta preço e margem. Bloquear por padrão.
Permitir alterar desconto do produto Impacta margem e política comercial. Bloquear por padrão.
Visualizar relatório tabela preço Consulta comercial. Liberar conforme função.
Cancelar pedido Interrompe venda ou fluxo operacional. Restrito.
Excluir pedidos Remove registro operacional. Bloquear por padrão.
Agrupar pedidos Impacta organização logística/operacional. Controlado.
Aprovar orçamento Avança negociação para etapa comercial relevante. Restrito conforme política da No Fire.
Preço triagem Impacta análise prévia de preço. Controlado.
Reabrir pedidos Reverte fluxo já avançado. Restrito.
Alterar vendedor Impacta responsabilidade e comissão. Restrito.
Alterar OBS item Permite ajuste de observação em item. Baixo/médio risco, liberar com critério.

Para vendedor comum, alterar valor, alterar desconto, excluir, cancelar, aprovar e reabrir devem nascer bloqueados.

14. Checkboxes de cliente, CRM, CADEX, WhatsApp e Nota Fiscal

Além dos grupos financeiros, compras e vendas, a PBCA035C pode conter permissões complementares que também devem ser revisadas.

Grupo Permissão Impacto Diretriz
Cliente Desbloqueia cliente Permite liberar cliente bloqueado. Restrito.
CRM Usuário do CRM Permite uso do módulo CRM. Liberar conforme função.
CRM Visualiza preço Exposição comercial. Controlado.
CADEX Usuário Acesso a rotinas técnicas/operacionais. Controlado por função.
CADEX Desativar equipamento Impacto técnico e operacional. Restrito.
WhatsApp Usa envio WhatsApp Comunicação direta com cliente. Liberar apenas a usuários autorizados.
WhatsApp Sessão WhatsApp Controle de sessão/canal de comunicação. Controlado.
Nota Fiscal Permite cancelar NF Impacto fiscal crítico. Restrito. Não liberar para vendedor comum.

Cancelamento de NF, desbloqueio de cliente e desativação de equipamento não são permissões administrativas simples.

15. Padrão recomendado por perfil

Abaixo está uma leitura operacional inicial para orientar a revisão dos checkboxes. A matriz definitiva deverá ser ajustada conforme validação da No Fire.

Perfil Checkboxes que podem fazer sentido Checkboxes que devem ser bloqueados por padrão
Vendedor Copiar pedido, visualizar preço/relatórios autorizados, alterar OBS item se validado. Alterar valor, alterar desconto, excluir pedido, cancelar pedido, aprovar orçamento, alterar vendedor, financeiro, cancelar NF.
RH Somente o necessário para cadastro básico, conforme orientação específica. Financeiro, compras, vendas, fiscal, perfil, restrição, exportação, checkboxes sensíveis.
Administrativo Contas a pagar/receber, baixa de títulos, conforme função. Aprovar, reabrir, alterar dados chave, fiscal crítico e permissões comerciais sem necessidade.
Financeiro Permissões financeiras necessárias à função. Permissões comerciais, fiscais ou estruturais fora da função.
Engenharia CRM, CADEX ou visualizações técnicas conforme função. Financeiro, alteração comercial, cancelamento, aprovação, desconto e NF.
Administrador Pode ter permissões amplas, se definido pela gestão. Não se aplica como bloqueio padrão, mas exige responsabilidade e rastreabilidade.

Perfil operacional comum não deve carregar permissões críticas por conveniência.

16. Procedimento de revisão dos checkboxes

Ao revisar um usuário na PBCA035C, o responsável deve seguir o procedimento abaixo:

  1. Confirmar que o usuário selecionado é o usuário correto.
  2. Confirmar função e área do usuário.
  3. Verificar quais checkboxes já estão marcados.
  4. Desmarcar permissões sem justificativa.
  5. Manter apenas permissões compatíveis com a função.
  6. Validar permissões críticas com a gestão.
  7. Conferir se a revisão da PBCA035 já foi realizada.
  8. Salvar somente após revisão completa.
  9. Registrar ou comunicar exceções relevantes.

O checkbox deve ser consequência da função, não da configuração que veio marcada na tela.

17. Checklist final da PBCA035C

Antes de considerar o usuário pronto para operação, conferir:

  1. O usuário correto está selecionado?
  2. A função foi confirmada?
  3. O perfil foi definido?
  4. Os programas foram vinculados na PBCA079A?
  5. O usuário foi revisado na PBCA035?
  6. Todos os checkboxes foram revisados manualmente?
  7. Permissões financeiras indevidas foram removidas?
  8. Permissões de compras indevidas foram removidas?
  9. Permissões comerciais críticas foram bloqueadas?
  10. Permissão de cancelar NF está bloqueada quando não aplicável?
  11. Permissões de alteração de valor/desconto foram bloqueadas quando não aplicáveis?
  12. Exceções foram validadas?
  13. Alterações relevantes foram comunicadas?

Sem revisão de PBCA035C, o acesso do usuário ainda não está fechado.

19. Erros que devem ser evitados

  • deixar checkbox marcado porque “já veio assim”;
  • marcar checkbox sem saber exatamente o que ele faz;
  • liberar alteração de valor para vendedor comum;
  • liberar alteração de desconto sem política definida;
  • liberar exclusão de pedido por conveniência;
  • liberar cancelamento de NF para usuário sem função fiscal;
  • liberar financeiro para usuário não financeiro;
  • revisar perfil e esquecer checkboxes;
  • revisar PBCA035 e não voltar na PBCA035C;
  • considerar usuário pronto apenas porque login e perfil foram criados.

O checkbox errado é perigoso justamente porque parece detalhe.

20. Conclusão final do Bloco 07

A PBCA035C deve ser tratada como uma tela dupla: cadastro de usuário e permissões internas.

A parte cadastral pode parecer simples, mas os checkboxes presentes na mesma tela podem conceder poderes relevantes dentro do sistema. Por isso, a revisão desses campos deve ser obrigatória em qualquer criação, alteração ou auditoria de usuário.

O acesso correto depende da combinação entre:

  • perfil adequado;
  • programas vinculados corretamente;
  • restrições revisadas na PBCA035;
  • checkboxes validados na PBCA035C;
  • governança operacional para acessos indiretos.

PBCA035C é onde o detalhe vira poder. Por isso, nenhum checkbox deve ficar sem revisão.
